# NFR-003 標準ライブラリ優先 要件定義書

## 概要

検索インデックスの実装において Python 標準ライブラリを優先するが、外部ライブラリの使用も許容する。

> **注記**: 本要件はセマンティック検索の精度・速度要件を達成するため、標準ライブラリ原則をベストエフォートに緩和する目的で作成された。この緩和はプロジェクトオーナーが承認済み。
>
> **現行ステータス（Issue #13 / #15）**: セマンティック検索（Embedding）は Issue #13 で doc-advisor から削除され、key + path I/F（REQ-001）は **標準ライブラリのみ**で実装されている（REQ-001 NFR-N01、外部依存ゼロ）。本要件の「緩和」は現行 doc-advisor には適用されず、史実として保持する。

## 前提条件

- なし

## 要件一覧

### ライブラリ選定方針

- Python 標準ライブラリ（sqlite3、json 等）で実現可能な場合はそちらを優先する
- 標準ライブラリでは精度・速度の要件を満たせない場合、外部ライブラリの使用を許容する
- 外部ライブラリを採用する場合、依存の追加理由と代替案の検討結果を設計書に記録する

### 適用範囲

- 検索インデックスの構築
- 検索の実行
- 検索結果のランキング

### エラーケース

| 条件                           | 動作                                         |
| ------------------------------ | -------------------------------------------- |
| 外部ライブラリが未インストール | エラーメッセージでインストール方法を案内する |

## 関連要件

- REQ-001 NFR-N01: 標準ライブラリのみ使用（Python 3.11 下限・外部 API キー不要）

> **Note（Issue #13 / #14 / #15）**: 本要件は当初セマンティック検索（Embedding）の精度・速度のために標準ライブラリ原則を緩和する目的で作成された。Embedding は Issue #13 で doc-advisor から削除済み。Issue #15 の key + path I/F は標準ライブラリのみで実装している（REQ-001 NFR-N01）。標準ライブラリ制約の最終的な見直し（PyYAML 採用の可否を含む）は Issue #14（`toc_utils.py` の YAML 処理を PyYAML ベースに移行）で扱う。本書本体の更新は #14 のスコープ。

> **PyYAML 採用は当面延期（2026-08-13 決定）**: 外部依存ゼロを維持する。したがって現行の「標準ライブラリのみ」は引き続き正である。なお PyYAML を採用しても、原本フロントマターの書き込みは代替できない（`fm_core.merge_frontmatter` は doc-advisor が所有するキー以外を原文のままバイト保持する行保存型マージであり、`safe_load` → `safe_dump` ではコメント・キー順・引用形式が失われる）。効果があるのは doc-advisor が全体を生成する YAML（`toc.yaml` / pending / checksums）の read/write とフロントマターの読み取りに限られる。
>
> **サポート下限は Python 3.11（2026-08-13 変更）**: 従来の 3.9 下限は `Path.is_relative_to` が使えることを根拠にした文法上の下限だったが、3.9 は 2025-10-31 に、3.10 は 2026-10-31 に upstream の EOL を迎える。EOL 版を下限に掲げることは未修正 CVE 上での実行を公式に許可することであり、下限は保守期限で決める（REQ-001 NFR-N01）。この変更は PyYAML 採用の可否とは独立である。
