# FNC-002 見落としゼロの検索精度 要件定義書

## 概要

doc-advisor の ToC 検索において、タスクに関連する文書を 1 件も見落とさない検索精度を実現する。返却する文書の件数に上限を設けず、関連する文書は全て返す（false negative の最小化を最優先する）。

## 前提条件

- ToC（`{category}_toc.yaml`）が最新の状態であること（変更検出は FR-03 / DES-005 を参照）
- 検索は `query-rules` / `query-specs` SKILL が `query_toc_workflow.md` に従って実行する

## 要件一覧

### 精度要件

- 関連する文書は全て検索結果に含まれる（False Negatives = 0）
- 件数制限を設けない。関連文書が 50 件あれば 50 件全て返す
- 迷ったら含める（過剰包含は許容、見落としは不可）。最終的な取捨は呼び出し元の AI がファイル本文を Read して判断する

### 検索対象のフィールド

ToC エントリの全メタデータフィールドを照合対象とする:

- タイトル（title）
- 目的（purpose）
- 内容詳細（content_details）
- 適用タスク（applicable_tasks）
- キーワード（keywords）

### カテゴリ分離要件

- rules / specs のカテゴリ分離を維持する
- 各カテゴリの ToC は独立して生成・検索される

### 検索方式

- AI が ToC YAML を **全量 Read** し、全エントリを理解してからタスクとの関連を判定する（grep やトークンマッチではなく、メタデータの意味理解による照合）
- ToC が大きく全量 Read が困難な場合（100 件超）の縮小読み込み手段は DES-005 / `query_toc_workflow.md` の Filter Procedure を参照

### 品質を担保する仕組み

見落としゼロは、**ToC メタデータの網羅性** に依存する。以下を品質の鍵とする:

- `keywords`: クラス名・メソッド名・ドメイン固有語など、タスク記述と照合される語を網羅する
- `content_details`: 文書固有の具体的な内容項目を列挙する（generic な項目ではなく、その文書を特定できる項目）
- `applicable_tasks`: その文書が必要になる具体的なタスク種別を列挙する

ToC 生成時（`doc-advisor:toc-updater`）にこれらのフィールドを充実させることが、検索精度の前提となる。

### エラーケース

| 条件                             | 動作                                                                                                         |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| ToC が古い（文書変更後に未更新） | 検索は実行するが、結果が古い可能性を呼び出し元に通知し、`/doc-advisor:create-*-toc` での再生成を案内する     |
| ToC が存在しない                 | 候補なし（空リスト）として扱い、`/doc-advisor:create-*-toc` の実行を案内する（query_toc_workflow.md の仕様） |
