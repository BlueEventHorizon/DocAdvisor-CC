# REQ-001: doc-advisor 要件定義書

## 概要

doc-advisor は、プロジェクトのドキュメント（ルール・仕様文書）を ToC（Table of Contents = キーワード／メタデータの検索インデックス）として自動的にインデックス化し、AI エージェントがタスクに関連する文書を素早く特定できるようにする Claude Code プラグインである。

検索方式は **ToC 検索のみ**。Embedding（セマンティック）検索は doc-advisor の責務外であり、query-docs プラグイン側で扱う（`BlueEventHorizon/bw-cc-plugins#77`）。

## 前提条件

| ID     | 要件                                                                                                                   |
| ------ | ---------------------------------------------------------------------------------------------------------------------- |
| PRE-01 | `.doc_structure.yaml` がプロジェクトルートに存在し、doc-advisor がランタイムで直接参照する文書構造設定ファイルである   |
| PRE-02 | `.doc_structure.yaml` は `/doc-advisor:setup-doc-structure` で作成、または手動配置する                                 |
| PRE-03 | `.doc_structure.yaml` がない場合、各 SKILL は `config_required` を検出し `/doc-advisor:setup-doc-structure` を案内する |

## 機能要件

### FR-01: ドキュメント管理

| ID      | 要件                                                                                                                               |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| FR-01-1 | システムは `rule` と `spec` の2カテゴリでドキュメントを管理する                                                                    |
| FR-01-2 | 各カテゴリは1つ以上のルートディレクトリを設定できる                                                                                |
| FR-01-3 | ルートディレクトリ配下のサブディレクトリ構造は自由とする                                                                           |
| FR-01-4 | 除外パターンにより、スキャン対象から特定のディレクトリを除外できる                                                                 |
| FR-01-5 | システムは `doc_type` でドキュメントを分類する。推奨7種（rule, requirement, design, plan, api, reference, spec）+ カスタムタイプ可 |
| FR-01-6 | `doc_type` とスキャンパスの対応は `.doc_structure.yaml` に `doc_types_map` として記述される                                        |
| FR-01-7 | ToC の各エントリにはファイルパスから判定した `doc_type` フィールドを自動付与する                                                   |

### FR-02: ToC 自動生成

| ID      | 要件                                                                         |
| ------- | ---------------------------------------------------------------------------- |
| FR-02-1 | システムは各ルートディレクトリ配下の `.md` ファイルをスキャンする            |
| FR-02-2 | システムは各ファイルからメタデータ（タイトル、目的、キーワード等）を抽出する |
| FR-02-3 | システムは抽出したメタデータを YAML 形式の ToC ファイルに出力する            |
| FR-02-4 | システムは差分更新（変更ファイルのみ処理）をサポートする                     |

### FR-03: 変更検出

| ID      | 要件                                                              |
| ------- | ----------------------------------------------------------------- |
| FR-03-1 | システムは SHA-256 ハッシュでファイル変更を検出する               |
| FR-03-2 | システムはチェックサムファイル (`.toc_checksums.yaml`) を管理する |
| FR-03-3 | システムはファイルの追加・変更・削除を検出する                    |

### FR-04: 並列処理

| ID      | 要件                                                                                |
| ------- | ----------------------------------------------------------------------------------- |
| FR-04-1 | システムは ToC 生成時、最大5並列で `doc-advisor:toc-updater` エージェントを実行する |
| FR-04-2 | システムは中断時に完了分（`.toc_work/`）を保持し、再開可能とする                    |

### FR-05: ドキュメント検索機能

| ID      | 要件                                                                                                                                |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| FR-05-1 | `/doc-advisor:query-rules` skill はタスクに関連する開発ルール文書のパスリストを返す（ToC 検索）                                     |
| FR-05-2 | `/doc-advisor:query-specs` skill はタスクに関連する仕様文書のパスリストを返す（ToC 検索）                                           |
| FR-05-3 | ドキュメント検索は `context: fork` で隔離実行し、メイン会話のコンテキストを汚さず、書き込み副作用を持たない（ADR-002）              |
| FR-05-4 | ドキュメント検索はユーザーが `/query-*` で直接呼び出せるほか、Claude が description マッチで自動トリガーできる                      |
| FR-05-5 | 検索は ToC YAML のメタデータ（title / purpose / content_details / applicable_tasks / keywords）を AI が読み込んで関連文書を特定する |
| FR-05-6 | 見落としゼロを優先する（false negative の最小化）。詳細は FNC-002 を参照                                                            |

### FR-06: セットアップ

| ID      | 要件                                                                                                                 |
| ------- | -------------------------------------------------------------------------------------------------------------------- |
| FR-06-1 | `/doc-advisor:setup-doc-structure` skill はプロジェクトをスキャンし、ディレクトリを rules / specs に分類する         |
| FR-06-2 | 分類結果はユーザー確認（AskUserQuestion）を経て `.doc_structure.yaml` に書き出す                                     |
| FR-06-3 | setup-doc-structure は外部スクリプト・追加パッケージに依存せず、Glob / Read / Write / AskUserQuestion のみで完結する |

## 非機能要件

### NFR-01: 依存関係

| ID       | 要件                                                            |
| -------- | --------------------------------------------------------------- |
| NFR-01-1 | Python スクリプトは標準ライブラリのみを使用する（pip 依存なし） |
| NFR-01-2 | システムは Python 3 で動作する。外部 API キーを必要としない     |

### NFR-02: 設定可能性

| ID       | 要件                                                                                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| NFR-02-1 | 各カテゴリのルートディレクトリは複数設定可能とする                                                                                                                       |
| NFR-02-2 | スキャンパターン（グロブ）と除外パターンは設定可能とする                                                                                                                 |
| NFR-02-3 | 並列処理数はコードデフォルトで定義する（`toc_utils.py`）                                                                                                                 |
| NFR-02-4 | `.doc_structure.yaml` は `root_dirs`（配列）、`doc_types_map`（辞書）、`patterns`（辞書: target_glob, exclude）で文書構造を定義する                                      |
| NFR-02-5 | doc-advisor 内部設定（toc_file, checksums_file, work_dir 等）はコードデフォルト（`toc_utils.py` の `_get_default_config()`）で定義し、`.doc_structure.yaml` には含めない |

## 用語定義

| 用語                  | 定義                                                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| カテゴリ              | ドキュメントの大分類。`rule`（開発ルール）と `spec`（プロジェクト仕様）の2種類。スクリプト CLI では `--category` 引数で指定する |
| ルートディレクトリ    | 各カテゴリのスキャン起点となるディレクトリ。複数設定可能                                                                        |
| doc_type              | ドキュメントの分類タイプ。推奨7種（rule, requirement, design, plan, api, reference, spec）+ カスタムタイプ可                    |
| .doc_structure.yaml   | doc-advisor がランタイムで直接参照する文書構造設定ファイル。`/doc-advisor:setup-doc-structure` で作成する                       |
| ToC                   | Table of Contents — ドキュメントのメタデータ検索インデックスファイル（YAML）                                                    |
| Skill                 | Claude Code のスラッシュコマンドとして登録される機能単位                                                                        |
| Agent                 | Claude Code の Agent ツールで起動されるワーカー（汎用 Agent またはカスタム Agent。doc-advisor では `toc-updater`）              |
| doc_structure_version | `.doc_structure.yaml` の形式バージョン。コメント形式（`# doc_structure_version: 3.0`）で記録する                                |
